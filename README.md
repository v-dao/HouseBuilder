# 房屋建筑软件

国标建筑施工图设计 / 施工过程模拟 / 工程量统计。

当前进度：**二维施工图编辑器（里程碑一）已完成**。
1564 项单元测试断言全通过，DXF 与 PDF 导出经第三方库（ezdxf / pypdf）交叉验证。

已实现的能力：

- **绘制**：直线、多段线（含圆弧段）、矩形、正多边形、圆、圆弧、椭圆、
  样条曲线、点、构造线/射线
- **编辑**：删除、移动、复制、旋转、缩放、镜像、拉伸、阵列（矩形/环形）、
  偏移、修剪、延伸、打断、圆角、倒角、分解、合并
- **捕捉**：端点/中点/圆心/象限点/交点/垂足/切点/最近点/节点/插入点/延长线，
  正交 F8、栅格捕捉 F9、极轴追踪 F10
- **标注**：线性/对齐/连续/基线/半径/直径/角度，按 GB/T 50001 第 11 章生成
- **符号**：标高、索引、详图、剖切、引出线、折断线、波浪线、轴线号
- **文字**：单行、多行（自动换行、九种对齐）、双击改文字；长仿宋 0.7 宽高比
- **填充**：GB/T 50001 附录的 30 余种材料图例 + 实心填充（剖切墙体 poché）
- **块**：定义/插入/属性块/编辑属性 + 27 个 1:1 建筑图库块（门窗/洁具/厨具/家具/楼梯）
- **建筑工具**：参数化轴网（自动编号、自动三道尺寸）、参数化墙体
  （中心线+厚度+洞口，墙线随洞口自动断开）、门窗插入、房间净面积、参数化楼梯、门窗表
- **国标规范**：GB/T 50001 线宽组与图线用途映射、图幅图框、标题栏、会签栏
- **图纸空间**：布局 + 视口 + 模型/图纸切换，出图所见即所得
- **文件**：自有格式 `.hbd`、DXF R12 读写（GBK 中文）、矢量 PDF（嵌入中日韩字体）、SVG、PNG
- **界面**：命令行 + 别名（中英文）、图层管理器、特性面板、撤销重做、设置持久化

尚未完成的部分见文末「后续按计划应做的部分」。

## 环境

| 项 | 值 |
|---|---|
| 引擎 | Godot **4.7.2 stable**（标准版，非 .NET，故只用 GDScript） |
| Godot 路径 | `$GODOT` |
| 外部依赖 | **零**。DXF 读写、几何内核全部自研 |
| 图形 | Vulkan / Forward+，`msaa_2d = 4x` 提供线条抗锯齿 |

## 运行

```bash
# 首次必须先导入，生成全局类缓存，否则 class_name 全局类不可见
"$GODOT" --headless --path . --import

# 启动软件
"$GODOT" --path .

# 单元测试（无头）
"$GODOT" --headless --path . --script res://tests/run_tests.gd

# 截图验证（必须带窗口，输出到 tests/out/）
"$GODOT" --path . --quit-after 1200 res://tests/capture.tscn
```

> **注意**：脚本报错后 Godot 不会自动退出。批量任务务必带 `--quit-after` 兜底。

## 已实现的关键能力

### 图纸数据模型
- 图元是 `RefCounted` **纯数据对象**，不挂场景树。DXF 映射、撤销、序列化、
  以及后续的 3D 派生共用同一份数据
- 基于操作记录的撤销栈（新增/删除/修改的净效果），不是整文档快照
- 所有变更经 `CadDocument` 的 `add_entity` / `remove_entity` / `mark_modified`，
  保证撤销记录与渲染脏标记一致

### 几何内核
- 解析曲线抽象（线段 / 圆弧 / bulge 多段线），渲染、求交、捕捉共用
- 圆弧按**屏幕像素矢高**自适应细分（0.25px），放大不露多边形棱角
- bulge ↔ 圆弧双向转换。**注意：正 bulge 的圆弧位于弦的右侧**（已推导验证，
  反直觉，详见 `src/geom/bulge.gd` 注释）
- 线段/圆弧/圆两两求交，含切线退化与角度范围判定
- 镜像变换会反转圆弧绕向，变换后按"起点+中点+终点"三点重建而非套角度公式

### 渲染
- 按「最终颜色 + 线宽档位」分桶，每桶**一次** `draw_multiline` 提交
- 视口剔除：先用包围盒筛掉视野外图元
- 抗锯齿由视口 `msaa_2d = 4x` 提供，不用逐图元 `antialiased`（会打断批量）
- 虚线/点画线在**模型空间**切分（周期不足 2px 时退化实线），缩放时疏密不变
- 文字在屏幕空间逐条提交，旋转用 `draw_set_transform` 建立局部坐标系

### 国标符合性
- **线宽组**：b / 0.7b / 0.5b / 0.25b，b 从 1.4/1.0/0.7/0.5 中选，下限 0.1mm
- **图线用途**按 GB/T 50104 分配：墙体柱 = 粗实线 b，门窗构配件 = 中粗 0.7b，
  尺寸与符号 = 中实线 0.5b，定位轴线 / 图例填充 = 细 0.25b
- **长仿宋**：对仿宋施加 0.7 横向压缩（`FontVariation.variation_transform`）
- **字高系列**：2.5 / 3.5 / 5 / 7 / 10 / 14 / 20 mm
- **标注**：尺寸界线超出尺寸线 2.5mm、45° 中粗斜短线起止符号 2.5mm、
  尺寸数字字高 2.5mm 居上居中、平行尺寸线间距 7~10mm

### 验证
- 204 项单元测试断言（几何内核 / 国标线宽 / 序列化往返 / 撤销重做）
- 截图验证工具，出图到 `tests/out/`
- **截图前必须预热字体图集并等待 ≥12 帧**，否则会拍到白色占位纹理，
  看起来像"所有文字变成实心方块"（详见 `docs/引擎特性与坑.md`）

## 后续按计划应做的部分

里程碑一（二维施工图编辑器）已完整交付。原计划的后续里程碑：

| 阶段 | 内容 |
|---|---|
| M2 | 参数化三维：2D 数据自动生成墙板柱梁 → Manifold 布尔开洞 → LightmapGI 烘焙 |
| M3 | 施工工序：打灰/浇筑、排砖、钢筋绑扎（16G101）、抹灰装修分层 + 工程量统计 |
| M4 | 规范校核：GB 50300 / GB 50203 / GB 50204 / GB 50210 合规检查与报表 |

另有两处已知的、未完成的工作，已在 `docs/性能实测与瓶颈分析.md` 中写明诊断与解法：

1. **渲染性能**：十万图元全可见时一帧 274ms，超出 16.7ms 的预算。
   拾取与框选已达标（3.3ms / 7.5ms）。彻底解决需要把几何改为
   **模型空间绘制 + 画布变换**，让 GPU 承担坐标变换 ——
   这是结构性重构，需一次做完，不宜半途而废。
2. **鼠标移动时的无谓重绘**：十字光标与几何在同一个 CanvasItem 上，
   把光标挪到独立图层即可让鼠标移动不再触发几何重绘。

## 一些工程取舍的记录

这些取舍都有明确的理由，改动前建议先读 `docs/` 下的三份文档。

- **DXF 选 R12 而非 R2000+**：R2000 需要完整的 handle/owner 体系与
  CLASSES/OBJECTS 段，少一项 AutoCAD 就打不开；R12 结构简单，
  各家 CAD 都能读。交流图纸的核心诉求是"对方能打开"。
  代价是 R12 不承载图层线宽（组码 370 是 R2000 才引入的）——
  国内 CAD 的线宽本来就来自打印样式表按图层颜色映射，不存在图里。
- **PDF 嵌入整份字体而不做子集化**：simfang 10.5MB，压缩后约 5.7MB。
  换来"任何阅读器都能正确显示中文"。子集化能大幅减小体积，
  但要重建 glyf/loca/cmap 表，出错风险高，留待后续。
- **图元与场景树解耦**：CAD 实体是 RefCounted 纯数据对象。
  DXF 映射、撤销、序列化、后续的三维派生共用同一份数据。
- **撤销栈记录操作的净效果**而非整文档快照，十万图元下内存才可控。
